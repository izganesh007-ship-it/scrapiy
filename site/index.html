01

What it does

Everything the $29–500/month tools charge for — as ~700 lines of TypeScript you can read.

a.

Auto-detection

Finds the container that repeats across a listing, then pulls name, price and link from every instance. No selector writing needed.

scan(url) → 20 items · selector: li
b.

Visual selector

Load the page, click a card, pick its fields. Saved as a reusable recipe — the point-and-click flow, minus the black box.

item: .product-wrapper · price: span[itemprop=price]
c.

Pagination

Follows rel="next" links or ?page= parameters and merges everything into one dataset. Stops at dead pages automatically.

{mode:"page_param", max_pages:50} → 12 items / 2 pages
d.

Schedules

Any recipe can re-run every N hours on a cron trigger. Price monitoring that costs nothing to leave on.

POST /api/recipes/:id/schedule {"intervalHours":24}
e.

REST API

Run recipes from Python, Sheets, n8n, cron — anywhere HTTP works. Keyed, rate-limited, CSV or JSON out.

curl -H "X-API-Key: …" -d '{"recipe_id":"…"}' /api/v1/run
f.

JS rendering

JS-only sites escalate to Cloudflare's headless browser automatically — same call, no extra infrastructure to run.

tier 1 static → tier 2 browser (10 min/day free)
02

The whole story is four steps

Every scraper — from a $500 SaaS to a ten-line script — does exactly this. The demo walks each step against a real page.

01 FETCH

Download

Gets the page's HTML with real browser headers — the same bytes your browser receives.

02 DETECT

Find cards

Scans siblings for a container that repeats — that repetition is the product grid.

03 EXTRACT

Pull fields

Reads name, price, link from every card. Your selectors override the guesswork.

04 EXPORT

Deliver

CSV, JSON, or a saved recipe your code can call forever after.
